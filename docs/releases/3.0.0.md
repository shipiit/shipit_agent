## shipit-agent 3.0.0

shipit-agent is an independent agent library: its own loop, tools and SDK
layer, with no dependency on the Claude Agent SDK. This release brings its
features and defaults in line with that SDK and Claude Code, under the same
API names, on every provider shipit supports. Several defaults changed; see
docs/guides/upgrading.md for each one and how to restore the old behaviour.

### The SDK API (`shipit_agent.sdk`)

- `query()` streams typed messages (`SystemMessage`, `AssistantMessage`,
  `UserMessage`, `ResultMessage`, `StreamEvent`); `AgentOptions` takes the
  SDK's option names.
- `AgentClient`: a multi-turn session with interrupt, model and permission
  changes mid-session, and file checkpoints with `rewind_files`.
- Saved sessions: list, read, rename, tag, resume and fork.
- In-process MCP tools with `@tool` and `create_sdk_mcp_server`.
- `AskUserQuestion` through `can_use_tool`, and streaming input.
- MCP servers over stdio, SSE, HTTP or in-process; `continue_conversation`,
  `add_dirs` (folders beside the project for the file tools), `env`,
  `betas` and `max_thinking_tokens`.
- Results carry the SDK's fields: subtype, turns, durations, cost, usage,
  permission denials, stop reason, structured output. Usage has the SDK's
  shape for every provider, so cached input is counted the same everywhere.

### Harness, permissions and hooks

- Claude Code plugins (skills, commands, sub-agents, hooks, MCP servers),
  settings files (opt-in) and shell command hooks.
- Permission rules in the SDK's syntax (`Bash(rm *)`, `Edit(src/**)`,
  `WebFetch(domain:...)`, `mcp__server__*`), checked in the SDK's order;
  `allowed_tools`, `disallowed_tools`, `max_turns`, `dontAsk` mode.
- All ten SDK hook events, including pre-compact, sub-agent start/stop and
  permission requests; a hook may `defer` a call to resume it later.
- User-defined sub-agents; background tasks the model is told about, and
  `task_stop`.

### The loop and tools

- No step limit by default; `max_iterations` and `max_budget_usd` are opt-in.
- Read-only tool calls run in parallel by default.
- Claude Code's working set of tools stays resident; others are found with
  `tool_search`. Skills load on demand.
- Bash: a full shell under permissions, a two-minute default timeout, long
  commands continue in the background, and a command that does nothing is
  refused.
- `fallback_model`; retries on rate limits, overloads, server errors and
  dropped connections.
- New, off by default: `clear_tool_results` drops old tool results from each
  request on very long runs.

### Cost and speed

- The fixed prompt sent on every turn is about 42% smaller: each tool's
  guidance keeps only the rules that prevent mistakes.
- Measured with the new benchmark (`scripts/bench`, 18 tasks checked by
  outcome): on Gemma 4 31B the 16 core tasks went from 169,666 to 108,649
  input tokens with all still passing, and an eight-module rename that ran
  out of turns now finishes in 11.

### Fixes worth knowing

- Without the `anthropic` package, Anthropic requests no longer silently go
  to gpt-oss on Bedrock; they raise with the install command.
- A background sub-agent's whole work shows in the live display.
- The native Anthropic adapter sent shipit's tools in OpenAI's shape, so the
  API rejected every request with a tool; they are now converted. (It went
  unseen because the silent Bedrock fallback answered instead.)
- Streamed text could arrive after `run_completed`, so a stream showed the
  answer after the run ended and the transcript showed it twice.
- Every current Claude model, gpt-oss and Gemma 4 on Bedrock are priced at
  their own rates.

### Upgrading

Read docs/guides/upgrading.md. In short: set `max_iterations` if you relied on
the old step limit, check `deny`/`allow` lists against the wider rule
matching, name `setting_sources` to read settings files, and install
`anthropic` to use Claude directly.
